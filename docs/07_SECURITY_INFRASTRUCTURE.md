## Overview

데이터베이스와 배포 인프라를 **선택하지 않은** 프로젝트다. 보안의 핵심은 "저장하지 않는 것"과 "사용자 입력을 신뢰하지 않는 것"이다.

## 데이터 처리 원칙

| 데이터 | 위치 | 보존 |
|---|---|---|
| 계정(이름·이메일·ID·비밀번호 해시) | 브라우저 JS 메모리 (Zustand) | 새로고침·탭 종료 시 삭제 |
| 로그인 상태 | 브라우저 JS 메모리 | 로그아웃·새로고침 시 삭제 |
| 분석 결과 | 브라우저 JS 메모리 | 로그아웃·새로고침 시 삭제 |
| 업로드 이미지 | 서버 요청 메모리 (BytesIO) | 응답 후 즉시 폐기 |
| AI API 키 | 서버 환경 변수 `.env` | 코드·Git에 포함 금지 |

금지: DB, ORM, 서버 파일 저장, localStorage, sessionStorage, 쿠키, Zustand persist

## 인증 관련 주의

- 메모리 로그인은 **데모 수준**이며 실제 보안 인증이 아니다. 발표·문서에 명시한다.
- 비밀번호는 평문으로 두지 않고 SHA-256 해시로만 메모리에 보관한다.
- 서버 API는 로그인 여부와 무관하게 동작한다(서버에 사용자 개념 없음).

## 입력 검증

### 이미지
- 프론트엔드와 서버 모두 확장자·MIME·크기(10MB) 검사
- 서버는 `Image.open` + `verify()`로 실제 이미지인지 확인
- 픽셀 폭탄 방지: `Image.MAX_IMAGE_PIXELS` 제한(예: 40MP), 초과 시 거부
- 로그에 이미지 내용·파일명 외 정보 기록 금지

### HTML/CSS (개발자 방식2)
- 사용자 HTML을 서버에서 실행하지 않는다.
- 브라우저에서 `<script>`, `<iframe>`, `<object>`, `<embed>`, `on*` 속성, `javascript:` URL 제거
- `sandbox` iframe (스크립트 비허용)에서만 렌더링, 외부 리소스 로드 차단(CSP `default-src 'none'; style-src 'unsafe-inline'`)
- 입력 크기 제한 (HTML+CSS 합계 500KB)
- 서버는 색 값과 선택자 문자열만 받으며 형식(HEX 정규식) 검증

### API 공통
- Pydantic으로 요청 스키마 검증
- 내부 예외·스택트레이스를 응답에 노출하지 않음
- CORS 허용 출처를 환경 변수로 제한
- AI 엔드포인트 요청 크기·타임아웃(20초) 제한

## AI 호출

- 키는 `ANTHROPIC_API_KEY` 환경 변수로만 주입, 없으면 AI 기능 비활성(기본 문장)
- 사용자 이미지를 AI에 보내지 않는다. 분석 결과 JSON(색·수치·문제 목록)만 전송
- 프롬프트에 "수치를 바꾸지 말고 설명만" 지시, 응답 수치는 사용하지 않음

## 인프라

- 현재 단계: 로컬 개발 (backend `:8000`, frontend `:5173`)
- 배포는 추후 결정. 서버가 stateless이고 DB가 없어 정적 호스팅(프론트) + Python 호스팅(백엔드) 조합으로 쉽게 배포 가능
- 배포 시 필수: HTTPS, `ALLOWED_ORIGINS` 설정, `.env` 비공개
