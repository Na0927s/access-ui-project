## AI 바이브 코딩 방식

```
요구사항 정의 → docs 명세 → Claude에게 기능 단위 구현 요청 → 코드 생성
→ 팀원 코드 분석 → 실행·테스트 → 오류 확인 → 수정 요구사항 작성 → 재테스트 → Git 반영
```
- 한 번에 전체를 만들게 하지 않는다. 기능 하나씩 요청한다.
- 요청할 때 `.claude/CLAUDE.md` 규칙과 해당 docs 문서를 함께 제시한다.
- AI 생성 코드는 테스트 통과와 팀원 설명 가능 여부를 확인한 뒤 병합한다.
- 팀이 직접 결정할 것: 임계값, 점수 산식, WCAG 적용 수준, 추천 선정 방식, AI 역할, 보안 정책, 테스트 기준

## 코드 규칙

- Python: 타입 힌트, 서비스 함수는 순수 함수, 이미지 I/O는 라우터에서만
- TypeScript: `strict`, API 응답 타입을 `src/api/types.ts`에 정의
- 주석은 영어, 문서는 한국어
- 커밋: Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`)
- 브랜치: `main` 직접 푸시 금지, 기능별 브랜치 → PR → 리뷰

## 코드 리뷰 체크리스트

- [ ] localStorage·sessionStorage·쿠키·Zustand persist 사용 없음
- [ ] 비밀번호 평문 저장 없음 (bcrypt 해시, rounds=12)
- [ ] 인가가 `Authorization: Bearer` 토큰에서 user_id를 추출 (user_id를 URL 경로로 받지 않음)
- [ ] JWT·영속 세션·세션 쿠키 사용 없음 (in-memory opaque token만)
- [ ] 업로드 이미지 바이트를 DB·디스크·로그에 저장 없음 (SHA-256 해시만 캐시 키)
- [ ] 비로그인 사용자의 분석 결과를 DB에 저장 없음 (로그인 사용자만 영속화)
- [ ] 판정·선택 상태를 색만으로 표시하지 않음 (아이콘·텍스트 병행)
- [ ] 사용자 모드에 문제 해결 방법/요약 영역 없음 (개발자 모드 전용)
- [ ] 접근성 점수·점수 고지 문구 노출 없음 (판정 PASS/WARNING/FAIL과 설명만)
- [ ] 핵심 계산(cvd, color, wcag, recommend)에 테스트 있음
- [ ] 비밀 키 하드코딩 없음 (`ANTHROPIC_API_KEY`는 backend/.env에만)

## 발표 포인트

- "AI가 코드를 만들었다"가 아니라 "AI를 활용한 설계-구현-검증 프로세스를 구축했다"
- 분석 → 진단 → 개선 → 재검증 구조
- 한계(이미지 추정, 동적 UI, in-memory 세션 토큰은 서버 재시작 시 소멸)를 솔직하게 설명
