# ColorLens CVDS 개발일지

## 2026-11-16 작업 내용

### 1. 분석 중 스피너를 검사 버튼 안으로 이동

#### 배경
- 검사 진행 중 로딩 표시가 검사 버튼 아래 별도 영역에 표시되고 있었음.
- 버튼이 이미 `disabled` 상태로 바뀌는데 로딩 표시가 분리되어 있으면 시선이 두 곳으로 갈라짐.
- "분석 중"이라는 상태를 버튼 자체에 표현하는 것이 직관적이라는 피드백.

#### 구현 내용
- `frontend/src/pages/DeveloperModePage.tsx`, `frontend/src/pages/UserModePage.tsx`:
  - 검사 버튼 내부에 스피너(`size-4 animate-spin rounded-full border-2`)를 배치.
  - 텍스트는 `loading ? t('inspecting') : t('inspect')`로 전환.
  - `aria-busy={loading}` 유지로 스크린리더에 진행 중 상태 전달.

### 2. 첫 검사 직후 펼침 상태 (결과는 펼침, 문제 해결 방법은 접힘)

#### 배경
- 검사 직후 결과가 화면에 나타날 때 접기 상태가 이전 검사의 상태를 그대로 이월하는 문제.
- 사용자가 보고 싶은 건 "결과 내용"이 먼저이고, "문제 해결 방법"은 그다음 단계.
- 따라서 첫 검사 직후에는 결과 내용은 펼쳐 보이고, 문제 해결 방법은 접힌 상태가 자연스러움.

#### 구현 내용
- `frontend/src/pages/DeveloperModePage.tsx`:
  - `codeDetailOpen`(코드 모드 결과 표) 상태 추가, 기본값 `true`.
  - `inspect()` 실행 시 `setSolutionsOpen(false)` + `setCodeDetailOpen(true)`로 리셋.
  - 이미지 모드 `ResultSummary`에 `collapsible` prop 전달 (상세 영역 접기/펼치기, 기본 펼침).
- `frontend/src/components/ResultSummary.tsx`:
  - `collapsible` prop 추가. `true`면 상세 영역(주요 색상/발견된 문제/추천 색상)을 접었다 펼침.
  - `open` 상태 기본값 `true` (첫 검사 직후 펼침).
  - `useEffect`로 `data` 변경 시 `setOpen(true)`로 리셋 (다른 기록 열거나 새 검사 시 이전 상태 이월 방지).
  - 판정 + 요약 설명 상자는 항상 보이도록 유지.
  - 접기 헤더를 코드 모드(`CodeResultDetail`)와 동일한 "제목 + 펼쳐보기/접기 + ▲/▼" 패턴으로 통일.

### 3. 코드 검사 결과를 판정별 묶음으로 그룹화

#### 배경
- 코드 검사 결과 표가 판정과 무관하게 나열되어 있어, FAIL이 어디 있는지 한눈에 파악하기 어려웠음.
- FAIL → WARNING → PASS 순으로 묶어 보여주면 심각도 우선순위가 명확해짐.

#### 구현 내용
- `frontend/src/components/CodeResultTable.tsx` (신규):
  - `GROUP_ORDER: Verdict[] = ['FAIL', 'WARNING', 'PASS']` 순서로 그룹화.
  - 각 그룹 머리에 `VerdictBadge` + 개수 표시, 표 내부에서는 판정 열 생략 (중복 제거).
  - 빈 그룹은 표시하지 않음.
- `frontend/src/pages/DeveloperModePage.tsx`:
  - 기존 결과 표를 `CodeResultTable`로 교체, 접기/펼치기로 감쌈 (기본 펼침).

### 4. 문제 해결 방법 제목을 박스 헤더 안으로 통합

#### 배경
- "문제 해결 방법" 제목이 배경에 떠 있고 카드만 박스로 감싸져 있어 시각적 일관성이 떨어짐.
- "결과 내용"과 동일하게 제목을 박스 헤더 안에 두는 것이 자연스러움.

#### 구현 내용
- `frontend/src/pages/DeveloperModePage.tsx`:
  - 솔루션 제목을 접기/펼치기 헤더 안으로 이동.
  - `InfoPopover`(ⓘ)도 헤더 안에 포함 (이미지·코드 모드 모두).
  - "↓ 문제 해결 방법 보기" 원형 버튼 제거 (중복 토글 역할).

### 5. 결과 내역 코드 모드 상세를 하나의 박스 4섹션으로 통합

#### 배경
- 결과 내역에서 코드 모드 기록을 열었을 때 판정·표·해결 카드·요약이 분산되어 표시되었음.
- 검사 화면과 구조가 달라 일관성이 부족.

#### 구현 내용
- `frontend/src/components/CodeResultDetail.tsx` (재작성):
  - 하나의 박스 안에 4섹션을 구분선(`border-t`)으로 나누어 배치:
    1. 판정 + 결과 메시지 (항상 보임)
    2. 결과 내용 — `CodeResultTable` (접기/펼치기, 기본 펼침)
    3. 문제 해결 방법 — `SolutionCards` (접기/펼치기, 기본 접힘, 있을 때만)
    4. 요약 통계 (항상 보임)
  - `renderSummary()` 헬퍼로 검사 화면 코드 모드 요약과 동일 구조 유지.

### 6. 이미지 결과 → SolutionBox 변환 함수 분리

#### 배경
- `DeveloperModePage`에 인라인으로 있던 이미지 결과 → `SolutionBox` 변환 로직이 결과 내역에서도 필요.
- 두 페이지에서 같은 로직을 중복 구현하는 것을 피하기 위해 유틸로 분리.

#### 구현 내용
- `frontend/src/utils/imageIssuesToBoxes.ts` (신규):
  - `imageIssuesToBoxes(data: ImageAnalysis): SolutionBox[]` 함수.
  - 이슈 목록과 추천 색상 목록을 인덱스로 짝지어 변환.
  - 조건부(CONDITIONAL) 등급은 피하고, 없으면 첫 후보 사용.
  - `DeveloperModePage`(검사 화면)와 `ResultHistoryPage`(결과 내역) 양쪽에서 재사용.
- `frontend/src/pages/DeveloperModePage.tsx`:
  - 인라인 변환 로직 제거, 유틸 import로 교체. `SolutionBox` 타입 import 제거.

### 7. 결과 내역 이미지 모드를 검사 화면 결과와 동일 구조로 동기화

#### 배경
- 결과 내역에서 이미지 모드 기록을 열었을 때, 검사 직후에 봤던 결과 화면과 레이아웃이 달랐음.
- "검사를 했을 때 나온 결과들이 사진 제외 그대로 결과 내역에 나오게 해달라"는 요청.
- 사진(`ResultCompare`/`ImprovedCompare`)은 결과 내역에서 의미가 없으므로 제외하고, 나머지는 검사 화면과 동일하게.

#### 구현 내용
- `frontend/src/pages/ResultHistoryPage.tsx`:
  - 이미지 모드 상세를 `ResultSummary`(collapsible) + 문제 해결 방법(접기/펼치기, 기본 접힘) + 요약 통계 구조로 조립 — 검사 화면과 동일.
  - `solutionsOpen` 상태 추가, `openId` 변경 시 `useEffect`로 `false` 초기화 (다른 기록 열 때 접힘 상태).
  - 이미지 모드 요약 통계: `imageResult` 기반 `sumIssues`/`sumColors`/`imagePriority`/`sumNext` (검사 화면과 동일 로직).
  - 사용자 모드 기록은 규칙 7에 따라 문제 해결 방법·요약 통계 숨김 (개발자 모드만).
- 코드 모드는 기존 `CodeResultDetail`(박스 4섹션) 유지.

#### 시도했던 접근 (폐기)
- 처음에는 이미지 모드도 코드 모드와 동일한 "하나의 박스 4섹션" 구조(`ImageResultDetail` 컴포넌트)로 통합 시도.
- 하지만 "검사 화면 결과를 사진만 빼고 그대로 결과 내역에"라는 요청에 맞추기 위해 폐기하고, 검사 화면 레이아웃을 그대로 복제하는 방식으로 변경.

### 8. 탭 레이아웃 시프트 제거

#### 배경
- 결과 화면 탭 전환 시 `border` 두께 차이로 1px 레이아웃 시프트 발생.

#### 구현 내용
- `frontend/src/pages/DeveloperModePage.tsx`:
  - 탭 버튼을 `border` → `border-2` 고정 (선택/미선택 모두 동일 두께).
  - 선택 탭은 `border-ink bg-ink text-white`, 미선택은 `border-rule bg-white`로 색상만 구분.

## 규칙 준수 사항

- **규칙 7 (화면 규칙)**: 사용자 모드 기록에는 문제 해결 방법 카드·요약 통계를 표시하지 않음 (개발자 모드만).
- **규칙 8 (서비스 자체 접근성)**: 접기/펼치기 버튼에 `aria-expanded` + ▲/▼ 표시자로 시각·스크린리더 모두에 상태 전달. 판정은 색뿐 아니라 아이콘·텍스트 함께 표시.
- **규칙 1 (저장 정책)**: 접기 상태는 컴포넌트 메모리 상태만 사용, `localStorage`/`sessionStorage`/Zustand `persist` 사용하지 않음.
