## 이미지 분석 흐름 (사용자 모드 / 개발자 방식1)

1. 프론트엔드가 파일 형식·크기를 1차 검증
2. `multipart/form-data`로 이미지와 `cvd_type` 전송
3. 서버가 형식·크기 재검증, `Image.open(BytesIO)` → `verify()`로 손상 확인
4. RGBA는 흰 배경과 합성, 분석용 사본은 긴 변 1200px 이하로 축소
5. `cvd.simulate_image` → 시뮬레이션 PNG (base64)
6. `palette.extract` → 주요 색상과 비율
7. `analyzer`가 색상 쌍별로 대비율·원본/변환 OKLab 거리 계산 → 판정
8. `recommend`가 문제 색에 대해 후보 생성 → 재검증 통과분만
9. `scoring`이 점수 산출
10. JSON 응답. **이미지 바이트는 요청 처리 후 폐기**, 디스크 저장 없음
11. 프론트엔드가 `resultStore`에 추가하고 화면 표시

## 개발자 방식2 흐름 (HTML/CSS)

1. 프론트엔드가 `DOMParser`로 파싱 후 `<script>`, `on*` 속성, 외부 리소스 제거
2. `sandbox` 속성(스크립트 비허용) iframe에 렌더링
3. 텍스트를 가진 요소마다 `getComputedStyle`로 색, 배경(투명이면 부모로 거슬러 올라감), 글자 크기·굵기 추출
4. 요소 목록(JSON)을 `/api/developer/analyze`로 전송
5. 서버가 요소별 대비율·판정·시뮬레이션 거리 계산, 문제 해결 박스(`solution_boxes`)와 CSS 수정안 생성
6. 프론트엔드가 상세 결과 표와 문제 해결 카드·요약 렌더링

## 인증 설계 (저장 없음)

- 백엔드에 회원 API가 없다.
- `authStore`가 메모리에 계정 목록을 보관. 비밀번호는 Web Crypto SHA-256 해시로만 보관(데모용, 보안 인증 아님)
- 새로고침하면 JS 메모리가 초기화되어 계정·로그인·결과가 모두 사라진다.
- 로그아웃 시 `currentUser`와 `resultStore`를 비운다.
