## Overview

> "내가 보는 화면이 모든 사용자에게 똑같이 보일까?"

ColorLens는 웹 UI의 색상이 색각이상 사용자에게도 충분히 구분되는지 분석하고, 문제가 있으면 개선 방법을 제안하는 웹 서비스다. 단순히 "색이 예쁜가"가 아니라 **색상이 정보를 전달하는 수단으로 쓰이고 있는지, 그리고 색각이상 환경에서도 그 정보를 구분할 수 있는지**를 판단하는 것이 핵심 문제다.

## 해결하려는 문제

- 빨간색과 녹색 등 특정 색 조합을 구분하기 어렵다.
- 비슷한 색의 버튼·상태 표시·그래프 범례를 구분하기 어렵다.
- 오류/성공 상태를 색상만으로 전달하면 정보를 놓친다.
- 텍스트와 배경의 명도 차이가 부족해 읽기 어렵다.
- 색만 바꿔서는 다른 UI 요소와의 관계 때문에 개선되지 않을 수 있다.

## 차별점

기존 방식이 "색 입력 → 대비율 → PASS/FAIL"에 그친다면, 본 서비스는 **분석 → 진단 → 개선 → 재검증** 구조를 가진다. 색각이상 시뮬레이션, 색상 의존 UI 탐지, 비색상 개선 제안, 추천 색 재검증을 한 흐름으로 제공한다.

## 핵심 제약

- 저장 정책은 로그인 여부에 따라 다르다. 비로그인 사용자의 분석 결과는 메모리에서만 처리하고 저장하지 않는다(새로고침 시 소멸). 로그인 사용자의 분석 결과는 SQLite DB에 영속화한다(히스토리·캐시·통계).
- 인증 토큰·세션은 서버 메모리에만 저장하고 브라우저 저장소(localStorage/sessionStorage/쿠키)에는 쓰지 않는다. (Zustand `persist` 금지)
- 비밀번호는 bcrypt 해시로만 저장하고 평문으로 보관하지 않는다.
- 업로드 이미지 바이트는 로그인 여부와 무관하게 DB·디스크에 저장하지 않고 서버 메모리(BytesIO)에서만 처리한다(캐시 키로 SHA-256 해시만 저장).
- AI는 계산하지 않고 설명·번역만 한다. AI 없이도 핵심 분석이 동작한다.
- 접근성 점수는 폐지했다. 사용자에게는 판정(PASS/WARNING/FAIL)과 설명만 제공한다.

## 한계 (발표 시 설명)

- 이미지 분석은 압축·안티앨리어싱 영향을 받는다. "CSS를 완벽히 분석"이 아니라 "사용자가 실제로 보는 화면 기준의 시각적 접근성 분석"이다.
- HTML/CSS 분석은 JavaScript로 동적 생성되는 UI와 hover 등 상태 변화를 완벽히 다루지 못한다.
- 인증은 in-memory 세션 토큰(opaque token) 기반이므로 서버 재시작 시 로그인이 풀린다. 단일 인스턴스 학교 프로젝트 규모에 맞춘 설계이며, 다중 인스턴스·영속 세션이 필요한 프로덕션은 Redis/JWT 등으로 교체해야 한다.
