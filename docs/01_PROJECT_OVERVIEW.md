## Overview

> "내가 보는 화면이 모든 사용자에게 똑같이 보일까?"

Access Ui는 웹 UI의 색상이 색각이상 사용자에게도 충분히 구분되는지 분석하고, 문제가 있으면 개선 방법을 제안하는 웹 서비스다. 단순히 "색이 예쁜가"가 아니라 **색상이 정보를 전달하는 수단으로 쓰이고 있는지, 그리고 색각이상 환경에서도 그 정보를 구분할 수 있는지**를 판단하는 것이 핵심 문제다.

## 해결하려는 문제

- 빨간색과 녹색 등 특정 색 조합을 구분하기 어렵다.
- 비슷한 색의 버튼·상태 표시·그래프 범례를 구분하기 어렵다.
- 오류/성공 상태를 색상만으로 전달하면 정보를 놓친다.
- 텍스트와 배경의 명도 차이가 부족해 읽기 어렵다.
- 색만 바꿔서는 다른 UI 요소와의 관계 때문에 개선되지 않을 수 있다.

## 제공 기능

1. 색각이상 시뮬레이션 (적색·녹색·청색 계열)
2. 주요 색상 추출과 사용 비율
3. 색상 간 구분 가능성 분석 (OKLab)
4. WCAG 대비율 검사와 PASS/WARNING/FAIL 판정
5. 접근성 점수 (자체 지표)
6. 문제 색상 탐지와 대체 색상 추천 + 재검증
7. 색상 외 구분 방법 제안 (아이콘, 텍스트, 테두리, 패턴 등)
8. 개발자 모드 문제 해결 방법 카드와 요약
9. AI 설명, Kr/En 전환
10. 로그인·회원가입·마이페이지 (저장하지 않는 세션 방식)

## 차별점

기존 방식이 "색 입력 → 대비율 → PASS/FAIL"에 그친다면, 본 서비스는 **분석 → 진단 → 개선 → 재검증** 구조를 가진다. 색각이상 시뮬레이션, 색상 의존 UI 탐지, 비색상 개선 제안, 추천 색 재검증을 한 흐름으로 제공한다.

## 핵심 제약

- 로그인 정보·분석 결과는 DB·서버·브라우저 저장소에 저장하지 않는다. 새로고침·로그아웃 시 사라진다.
- 업로드 이미지는 서버 메모리에서 분석한 뒤 즉시 폐기한다.
- AI는 계산하지 않고 설명만 한다. AI 없이도 핵심 분석이 동작한다.
- 접근성 점수는 공식 WCAG 인증 점수가 아니다.
